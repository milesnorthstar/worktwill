# Security policy

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/milesnorthstar/worktwill/security/advisories/new).
Do not disclose an unpatched vulnerability in a public issue or pull request.
A GitHub account is required for this channel.

Include the affected version or source commit, OS and architecture, impact, and
minimal reproduction steps using disposable example files. Relevant areas include
file authorization and identity, URL/network-target validation, and update verification.
Do not upload real documents, application databases, backups, credentials, signing keys,
or logs containing private filenames, paths, or URLs. Agree on a safe way to share
additional evidence within the private report if necessary.

WorkTwill is preview software maintained on a best-effort basis. Security fixes target
the latest published preview; older previews and arbitrary development commits do not
have a separate backport commitment. If no packaged fix is available, an advisory should
state the affected scope and available mitigation rather than imply a release exists.
There is no guaranteed response time, paid support SLA, or bug bounty program.

Please coordinate public disclosure with the maintainer so a fix or mitigation can be
communicated without exposing private report details.

## 安全漏洞反馈

请使用 [GitHub 私密漏洞报告](https://github.com/milesnorthstar/worktwill/security/advisories/new)，
不要在公开 Issue 或 PR 中披露尚未修复的漏洞；此入口需要 GitHub 账号。

请提供受影响版本或源码提交、系统与架构、影响和基于临时示例的最小复现步骤。
不要上传真实文档、应用数据库、备份、凭据、签名密钥或带私人文件名、路径、URL 的日志。
需要更多证据时，先在私密报告中约定安全的提供方式。

项目仍为预览版，维护者按实际能力响应；安全修复面向最新已发布预览版，不承诺旧版回补、
固定响应时限、付费支持 SLA 或漏洞奖金。公开披露前请与维护者协调修复或缓解措施。
