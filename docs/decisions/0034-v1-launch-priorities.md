# 0034：V1 双平台首发与收尾优先级

日期：2026-11-20。状态：用户明确Windows也首发，并进一步明确暂不需要网络盘、外置盘和云同步目录支持；其余事项按本轮讨论降低当前优先级，不将未执行写成通过。

## 问题与依据

持续执行任务把核心缺陷、特殊目录适配、发行准备和一周用户观测混作同一收尾条件，无法给出明确的工程交付边界。用户在核对剩余工作后明确Windows也要首发，并指出特殊目录、签名开源和用户留存/竞品对比的当前优先级较低。

## 决定

- 用户明确Git初始化、提交和上传不作为当前验收，工程完成后自行处理。当前交付本地候选、验证结果和已知问题，不创建仓库、不提交或上传，也不把无Git状态列为工程阻塞。
- Windows与macOS一并首发。两端本地目录的外部拖入、搜索、保存后取回、权限边界和原件安全优先完成，并分别取得原生证据。macOS通过不能代替Windows通过。
- 验收顺序进一步明确：用户已有Windows电脑，当前先完成Mac原生验收和独立阶段交付，再对接该Windows电脑验证；Windows未执行不阻塞Mac阶段收尾，双平台首发目标保持。当前不为Windows测试安装虚拟机或创建其他测试环境。
- V1仅承诺内置磁盘上的普通本地目录。用户进一步明确暂不需要网络盘、外置盘、OneDrive/iCloud等云同步目录，故将其专门适配移出V1开发与验收范围，替代上一轮仅“后排”的安排；支持说明标为暂不支持，不以已有通用路径处理推定支持。仍保留位置不可用时不误连、不破坏原件和引用的安全要求。本轮不新增特殊目录识别/拦截功能。
- 签名/公证、安装发行及开源发布准备在核心闭环后处理，不因尚未办理而反复执行本地功能检查。相应公开发布前仍核对发行方式和许可；不宣称未签名制品已完成签名，不擅自选许可证或发布仓库。
- 一周复用、真实用户反馈和竞品效率对比在试用后观察，不作为工程任务持续运行的退出条件。没有观测数据时保持待验证。
- 用户进一步要求“主要把项目工程先做好，这些可以后置”，明确当前先交付工程候选，发行准备和试用观测分阶段处理。备份恢复保留已有实现与检查，不继续扩展，也不把完整恢复矩阵当核心收尾前置；未验收入口仍需在相应公开发布前决定处理方式，不标为通过或直接删除。
- 当前每轮以明确缺口为目标，优先外部拖入，再核对本地保存取回、搜索与权限安全。无变更、无新失败和无未解疑点时不重复全量检查/构建；不再扩展特殊目录或重复做已有调研。Windows缺环境须说明具体未执行项，不能反复尝试、默认为通过或擅自取消双平台首发。

## 代价与验证边界

双平台首发仍需Windows构建及真实测试环境，是实质交付工作。特殊目录支持不属于V1，商业价值结论待试用后观察，发布说明须如实反映。此次依用户指示明确支持范围及优先级，不改变普通本地目录中F01–F14、U1–U8的核心行为、权限、性能预算或原件安全要求；历史证据保持原轮次，不将特殊目录未通过改写为通过。
