# 0031：在已有授权内及时收录通知中的新文件

日期：2026-11-20；迭代034。

## 实际问题

033只快速刷新已有路径。原生WPS另存副本后，原件内容、大小、mtime和inode不变，副本最终有独立UUID、无收藏或工作区继承，但mtime到首次发现仍为63.695秒。大目录扫描期间，新文件也需要及时可查，不能只优化已有文件的修改。

## 方案与职责

沿用033最多256条去重通知队列和单个刷新任务，不新增线程或无界任务。Store增加通知收录入口；原有仅刷新已知文件的入口保留原语义。通知不能建立目录或独立文件授权。

新路径必须处于当前有效、未暂停的目录授权内，并遵循自动扫描的默认跳过目录、用户排除项及应用数据目录排除。默认跳过规则提为Catalog与通知共用的函数，显式选择文件的规则保持独立。目录本身明确授权为根时，按原扫描规则处理；普通文件名恰为`.git`仍可收录。符号链接或非canonical路径不进入快速导入。

锁外读取文件事实，复用checked导入和事务guard。已有路径仍要求原UUID/路径/identity一致，不把同路径新对象自动接给旧引用；新路径在提交时复核尚未被其他任务收录、当前范围、权限版本和恢复epoch，身份由当前metadata及提交前复验确定。新副本不继承旧工作区或收藏，同物理对象的正常发现继续按现有identity去重。

checked导入在同一事务中将有效目录关系登记为当前扫描generation，代替固定0。该文件刚被重新读取并确认存在，正在收尾的旧目录枚举不能把它误判为未发现。不会因此更改扫描进度或提前登记整个根完成；后续删除仍由通知/全量扫描核对。
