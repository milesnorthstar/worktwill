# 0023：历史观察来源与重新指向影响确认

日期：2026-11-20。状态：迭代025实现；最终检查、规模测量与构建结果见验收记录，原生窗口仍须单列验收。

独立审查和真实临时文件红测发现：同路径替换的具体身份错误被扫描收尾覆盖为missing；重新指向后，旧opened事件借当前资源名称看起来像过去已打开新文件。只保存旧名称也不够：A撤权后将同一资源UUID指向已授权的B，会使A的旧名称借B权限重新出现。修复必须保持当前资源引用与历史观察授权两种事实。

schema v7增加三张私有表。activity_origins按事件保存观察时的资源UUID和物理identity；activity_root_scopes保存当时有效的root UUID、目录identity、相对位置及retired_location_valid；resource_relinks记录本次修复的源UUID、被合并UUID、原identity和所选identity。合并只更新活动指向的当前规范资源，历史来源不重写；被合并资源删除也不删除这些来源文本。它们不进入IPC DTO，不包含正文，不向源文件写元数据。

四个生产活动写入口在原有事务内保存观察名称及来源。读取历史文件活动，观察identity仍有当前记录时完全服从该对象当前授权，旧目录成员和历史范围不能覆盖已确认移出的事实。只有该identity已不再有当前记录，才允许原root UUID、物理锚点仍匹配且有效、原相对位置未被排除的历史范围参与授权；未知NULL identity保守隐藏。

全量既有安全回归揭示单靠“当前记录不存在”不够：A移出旧目录并撤销新目录后，再将匿名A重指B，会删除原identity记录而复活旧范围。因此跨身份relink在退休原identity前，按原记录最后已知位置是否仍属于每个历史root，持久更新retired_location_valid；原UUID、identity、锚点和相对路径保持原值。已确认移出旧范围的资格不能随UUID复用消失。此值不是新授权；仍须核当前root授权、identity和排除。未能确定仍在原root时收紧历史可见性，不猜测位置。

新对象授权不能授权旧观察。旧目录仍授权且原identity退休时仍在该范围，旧观察可以显示；如果当前规范资源已撤权，其资源DTO仍匿名且禁用。旧空名称仅在当前资源也有权限时回退当前名，避免泄漏新对象。当前格式文件活动缺来源不作可见兜底。

v6→v7使用短事务建表和绑定迁移时已有的identity/有效目录范围；旧事件的observed_resource_id为NULL，明确承认不能重建原始UUID，不把迁移时当前UUID伪装成历史来源。它只是迁移基准：迁移前已跨身份重新指向的旧事件，其原始名称归属无法重建，不能声称来源已被验证。不stat、不解析Bookmark。DDL或绑定失败全部回滚，版本保持6，可重试。恢复先在内存校验三表全部必要列与文件活动来源完整性，再按既有流程撤全部授权、使定位失效并严格递增版本；失败不覆盖当前库。

原生重新指向先读取源影响快照，确认所涉工作区和收藏，再用选择器取得不可由前端构造的文件身份。若目标已收纳，第二次确认显示所选位置及双方工作区/收藏，提交前重核源、目标、授权版本和影响关系。只比较相关事实，不因无关打开或扫描的全局revision变化废弃确认；身份、名称、位置、收藏、工作区增删/改名及上一修复事件变化则要求重看。同一review不能重复提交。确认文本不暴露UUID，撤权资源使用匿名名称。

原生提示仍使用现有系统对话框。动态列出全部工作区的字符串测试不等于大量工作区下窗口完整可读的视觉证据；系统选择器、合并确认和实际打开仍待原生窗口验收。

扫描收尾仅在本代次确实看见另一available对象占据同路径时保留identity_unconfirmed；替代对象真正消失后的后续扫描仍可变为missing，不让旧错误永久覆盖新的事实。

Document ID研究没有提供可安全替代物理identity的通用证据。本机APFS样本读取均为nil/0，未设置UF_TRACKED；Apple公开HFS测试还展示原对象删除后同路径新建继承旧Document ID。HFS行为不是APFS保证，但足以说明“非零且相等”不能不加验证就用来自动合并。025继续拒绝未知替换，保留明确修复入口；不创建tracking metadata，不把研究或手动修复算作Word安全保存通过。
