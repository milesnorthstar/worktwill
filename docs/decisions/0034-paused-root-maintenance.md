# 0034：暂停目录的指定维护与恢复快照边界

日期：2026-11-20；迭代037。

## 事实与问题

036原生夹具：两份TXT加入工作区，其中一份收藏；目录暂停后新增两个文件，再由终端在线移动整个目录。目录已定位到B且仍paused时，三秒后的只读观察中两条资源仍在A，新增资源0，后台大根仍running。后来界面和数据库确实恢复到B，不记为永久失联；现有watcher把暂停目录交回全量dirty，已有引用的核对仍需等待其他目录。

另一个确定性回归复现了文件恢复快照过宽：目录、授权与资源均未变，仅保存一个无关网页改变全局revision，就使文件位置回写返回permission_changed。此前原生大根扫描会持续更新revision，这个检查不适合作为文件位置回写的必要条件。

## 最小正确改动

Core增加refresh_root作为指定维护入口：未暂停目录继续正式scan_root，暂停目录只按file_roots中已有UUID稳定分页（每批100）核对候选。原refresh_roots复用同一暂停核对方法。每批复查目录有效、active/paused及物理身份，撤权停止；不枚举新目录项、不解除暂停。

Runtime沿用036的同一个16项队列和固定任务，不增加并发。watcher恢复位置后，无论暂停与否都送指定维护入口；由Rust根据当前状态决定扫描或只核对既有映射。

RootRecovery的文件位置回写检查目录UUID/path/active/generation/identity/Bookmark/valid、permission_version、原资源UUID/identity/location/归属，以及提交前实际文件身份和当前授权；不再要求无关全局业务revision相等。原生目录位置解析的Anchor.current仍保留完整revision检查。既有撤权、暂停、排除/包含、重授权、重新指向和恢复的负例全部保留并通过，未删除失败检查来交付。

## 原生复验

037新进程保持目录暂停、无独立file grant，再在线B→C。目录位置确认后的约1.66秒观察内，两条原UUID位置均更新到C，收藏和工作区保持，新文件仍0；后台大根仍running。原工作区打开第一份TXT，默认文本编辑器显示C的实际URL及SYNTHETIC_PAUSED_037_一，非模拟IPC。

暂停时搜索新增文件显示没有匹配资料；显式继续扫描后共4文件、两个新增文件才入库且可搜索。撤销授权后设置显示关联保留，工作区两条匿名引用，搜索不返回原文件名。通过选择器重新授权同一C后，原root/资源UUID、收藏、工作区、文件字节/mtime/inode保持，无重复资源。

文件系统移动由终端完成，不能提升为Finder图形移动或外部拖入通过。此为两文件的有限原生场景，不代表大量暂停映射的延迟保证。
