# 0020：macOS 独立文件的同物理身份定位恢复

日期：2026-11-20。状态：迭代022；单文件定位增量。完整原生工作台、根目录定位和安全替换仍未验收或实现。

019研究确认独立file grant改名或移位后，旧路径失效且目录重扫不能找到原对象。022为这条明确缺口增加普通NSURL Bookmark，不改变资源UUID或物理身份策略。Bookmark只给候选位置；候选必须同时匹配原资源、Bookmark绑定的物理身份及当前独立授权，未知替换仍拒绝继承。

schema v5增加私有file_locators(resource_id PK/FK ON DELETE CASCADE,identity,bookmark BLOB)。v4→v5建表与版本推进同事务，旧库不追认未知历史身份。定位数据不进入DTO、前端状态或源目录；不写自定义xattr、追踪文件或正文marker。恢复沿用全部历史授权撤销，保留定位记录也不能复活grant。恢复写回前显式校验三必要列，缺表/缺列的当前版本备份拒绝，保留当前库。

Core直接声明本机已锁定objc2 0.6.5、objc2-foundation 0.3.2的macOS依赖，仅启用所需Foundation feature，不升级版本或借用Tauri传递依赖。平台适配器只创建普通Bookmark、用WithoutUI|WithoutMounting解析本地file URL并返回路径/stale；拒绝远程host、非file URL和无效数据。NSError不透传原文，也不输出原始Bookmark。普通Bookmark不是security-scoped访问凭据，不据此承诺沙盒或发行权限。

显式单文件导入/重新指向在短SQLite写事务和gate之外创建候选Bookmark。提交沿原ingest/relink路径复核当前metadata和身份，在业务事务内保存定位数据。已有独立grant在当前位置仍能核实原对象时，重新扫描可以补建缺失Bookmark；普通目录扫描不会为全部索引文件创建定位数据。创建失败明确报告，不把未建定位数据写成已支持。重新指向换身份删除旧定位绑定，合并删除重复资源时由外键清除重复locator。

正常打开先沿原路径与授权复验；只有resource_unavailable/identity_unconfirmed才尝试一次单文件恢复。恢复在同一读事务捕获原UUID/identity/location、原Bookmark及permission/revision，释放gate后调用Foundation。候选普通文件的实际物理身份必须匹配；stale时先在锁外刷新Bookmark。原ingest短事务再次核对快照、active file grant、原绑定和原BLOB，再复验候选对象并更新路径/投影/metadata。即使调用者漏传expected_identity，恢复本身仍强制候选匹配FileRecovery.identity。没有把RwLock读锁升级成写锁、反转Catalog锁顺序或在锁内调用Foundation。

恢复后继续使用原UUID、工作区、收藏；单纯移动不伪造首次发现/正文修改，真实mtime/size变化沿既有事件规则。refresh_file_grants使用resolve返回的新路径，避免恢复后又按旧路径导入而回到missing。open/reveal在命令正常返回或出错时统一通知catalog-changed，因为路径可能已恢复而系统随后拒绝打开；opened仍只在系统接受后记录。此通知路径已编译和静态核对，未提升为原生IPC实测。

对单项Bookmark失败，刷新在gate/事务内重新核对原id/location与当前grant，并重验当前原件。只有仍适用的错误才保留，状态真正变化才bump revision；并发重新指向、同路径修复、撤权或版本变化后的过时响应不覆盖状态，也不继续报告旧错误。原件仍有效但缺locator时，创建失败仍明确返回且不标missing。scan_all先完成其他文件及无关根目录后返回有效定位错误；真实数据库/锁/内部错误仍立即失败。没有吞错或无限重试。

本机实际Foundation四项回归覆盖改名/同卷移动、新测试进程解析、删除同名新对象负例、无效/远程URL拒绝。领域十二项覆盖真实Bookmark与Store重开、两个工作区及收藏/字节/mtime、复制/替换、撤权/恢复、提交间mutation/relink/restore/原BLOB变化、候选身份硬约束、relink/merge、旧grant补建而非全量捕获、坏定位不阻塞无关根、过时错误丢弃及当前创建失败保留。另有v4迁移故障可重试及schema5备份缺表/缺列拒绝。最终全套数量及原始日志见ACCEPTANCE。

这些测试不代表完整WorkTwill进程/窗口退出重启或Office安全保存闭环。仅目录授权的文件和整个root移位仍未生产Bookmark自动定位；根物理锚点/有效scope/扫描代次/暂停/监听必须作为另一完整增量处理。跨卷、云目录、Document ID、身份变化的安全保存、Windows及签名发行继续独立验证，F01–F14/U1–U8范围没有因此缩减。
