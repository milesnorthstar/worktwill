# 0007：界面语言传递与输入状态

日期：2026-11-20。状态：迭代008已实施；原生窗口与系统选择器仍待实际验收。

设置页、文件重新定位与外部拖入使用同一界面语言。Rust DTO 定义 `UiLanguage`，六个涉及选择器或确认的命令显式接收语言：选择目录、选择文件、重新指向、备份、恢复、拖入提交。React 传递当前语言，长驻拖入监听从 ref 读取最新语言；语言只选择本应用标题、正文和确认/取消按钮，不参与授权判断或持久化。

原生确认文案集中在 `dialog_copy`。原有授权门槛、恢复前确认、独立合并确认与取消分支保持原流程。系统文件选择器的系统按钮仍随操作系统语言；后端业务错误尚未全部翻译，不能把本次变更写成所有英文流程通过。

排除目录输入由设置页按 root UUID 保存受控草稿。请求失败保留草稿；成功仅清理本次提交的根，且当前值必须仍等于提交值。刷新 overview 不覆盖尚未提交的内容。请求期间禁用相应输入及撤权入口，沿用页面的 busy 和 mutate，不新增业务状态所有者。

资料列表在请求期间优先显示读取状态，不将搜索或分类尚未返回写成空结果；加载占位使用 status 和 aria-busy，并隐藏空态操作。授权卡片文本使用明确的 location-copy，而不是依赖第几个子元素；文本允许长路径任意换行，保持按钮可达。该问题先由真实 DOM、计算样式及放大截图确认，再作局部修复。

UI/API 回归覆盖语言参数、切换语言后的拖入监听、草稿失败/成功与互不干扰、搜索/文件/网页加载状态。Chrome 合成夹具复核了 100% 和 200% 长路径布局。夹具不连接原生后端，不构成选择器、IPC 或实际拖入通过证据。验证结果见[验收记录](../ACCEPTANCE.md)。
