# 0004：日历按本地日期汇总并限制响应体积

日期：2026-11-20。状态：已实施于迭代005，真实原生使用验收仍待执行。

此前 `Store::timeline` 返回月份内每个不同时间点，React 再归日。同一个文件在一个月反复修改的合成磁盘基线中，100k/500k活动分别返回100k/500k日历点，响应约3.01/14.85 MB；这些数据只用于显示最多31天。

显示端逐本地午夜提供必填 `day_boundaries`。Rust校验2–32个有限、严格递增的边界、首尾与月范围一致、总跨度不超过32天；不允许缺参时退回无界时间点响应。日历和明细继续共享同一事务、类型、工作区和当前授权条件；选日只约束明细，不截断整月计数。返回有活动的当天边界和数量，最多31点。夏令时日保持23/25小时，不按UTC或固定24小时近似。

第一版按CASE分组虽然限制了体积，500k调用P95反而从754ms增至922ms，未作为最终方案。最终使用每日索引范围计数，并为文件有效时间创建派生表达式索引；`observed`仍用已有`at`索引。旧v3和恢复暂存库由迁移入口幂等创建索引，不改变业务表或schema版本。

代价是多一个活动索引和既有大库首次打开时的建索引成本。每次翻页仍会重算本月计数，列表仍按offset加快照版本校验；本决定没有把长期存储、深分页、原生时延或索引首次创建成本记为通过。最终可复核数字和前后日志见[迭代记录](../ACCEPTANCE.md)。规模库是单文件反复修改，不代表不同文件、真实扫描或窗口渲染。

新增检查覆盖本地边界、闰月、标准23/25小时DST、半开边界、重复/倒序/非有限/过量参数、多资源和网页、未授权文件、跨月、工作区及双时间模式；已有撤权、版本和分页测试保留。
