# 0024：同身份历史读取的权限查询复用

日期：2026-11-20。状态：迭代026实施，实际结果见验收记录；不改变schema7或跨端DTO。

025为历史名称增加观察来源授权后，100k混合实体首次月历API约624ms。026在相同正式SQL诊断器上重新测量16次：月历567–606ms，事件0.5–1.4ms，资源映射约0.6–2.1ms；16次独立正确性核对零错。主要成本是全月活动逐项执行的重复权限分支，不是返回过多日期点或深页offset。

activity_visible仍是overview、时间线列表、月历与诊断共用的唯一历史授权谓词。改为显式CASE：无资源的管理活动可见；网页用当前权限；文件必须有来源且观察identity非NULL。同identity分支由非空identity唯一索引保证原观察对象就是当前资源，原条件可归约为VISIBLE，因此只查一次当前权限，空旧名也已满足当前对象授权。

不同identity仍优先查询原观察对象的当前记录。标量子查询有记录时返回0/1，0必须保留；只有无记录返回NULL时，COALESCE才查询原历史scope。保留retired_location_valid、root物理锚点、有效授权和原相对排除条件。整个不同identity分支仍受“非空历史名，或当前规范资源也已授权”约束，防止空旧名借原对象权限暴露新对象名称。内部resources r只在原观察对象子查询中遮蔽外层r。

这不是缓存权限、放宽撤权或省略历史来源；不增加派生持久表，不改变schema7、目录定位、文件metadata或活动内容。已有已知移动/排除/匿名重指/恢复链全部保留，并补原观察identity在另一个UUID重新出现时的权限与空名回退回归。性能诊断和最终完整API分页均须实际执行后记录，不能用理论等价代替测量或将Core时间提升为原生可见延迟。

实际测量：CASE前16次月历567–606ms、中位583.008ms；CASE后16次398–410ms、中位404.641ms，约减少30.6%，各16次独立核对零错。完整API分页及候选包证据见本轮验收；该值不是原生窗口可见延迟，也不意味着月历成本已消除。
