# 0010：失败反馈保留双语并在显示时选择

日期：2026-11-20。状态：迭代012已实施；原生窗口与完整英文流程仍待真实验收。

PRD F10要求简中和英文核心流程。此前业务错误只携带中文message，React在catch中立即转成字符串；英文界面仍会显示中文，切换语言也不能更新已有失败报告。相同code可能表示不同原因，不能按code用一个通用英文覆盖具体原因。

Rust AppError强制提供code/message/message_en；构造函数要求每个业务错误同时给出中英文。IO和SQLite转换继续返回简短、无真实路径或SQL的正文；网页元数据错误保留超时、公网范围、格式和手动填写等具体原因。原生操作事件复用AppError。ImportItem的失败结果保留message和message_en，成功项两者为空；两个导入入口保持原有逐项状态与事务。错误和导入反馈不是持久业务记录，不改schema、成功操作回执、授权或业务分支，也不向Store传界面语言。

React复用api.errorMessage(error, language)，保存原始错误，在render时选择当前语言。App、表单、网页标题、时间线以{cause}|null独立表示错误存在，null/false/空串拒绝仍可显示通用失败；批量报告和拖入逐项反馈同样在显示时选择。资料名称仍使用用户数据；缺失名称的系统占位到显示时才翻译。前端自身构造的搜索响应、时间线版本与无标题反馈也保留双语内容。原生插件或JavaScript普通异常的现有message仍原样显示，不承诺自动翻译第三方正文。

切语言不重新提交、重抓网页标题或查询时间线。用户标题/输入和日期筛选保持原交互状态；明确重试才重新查询。时间线读取失败时，月历摘要与最近活动资料显示暂不可用，不将未知状态写成0条或真实空态。

UI/API回归使用实际errorMessage，mock仅替换IPC；覆盖现存错误切语言、草稿保留、常驻事件、非标准拒绝、标题失败/无标题、拖入逐项失败、批量失败与缺失名称、搜索失败、时间线失败/重试和空态恢复。Rust扩展真实导入/替换/捕获失败及URL拒绝用例，核对双语内容经过结果与序列化保留。Chrome模拟失败夹具只用于布局观察，不连接原生服务；系统对话框、第三方异常、未授权资源名称占位和原生操作仍按各自边界验收。
