# 0021：管理范围摘要区分目录与独立文件

日期：2026-11-20。状态：迭代023；正式App交互状态与样式沿用，不改变领域授权。

仅有file_grants而没有目录root时，旧首页以hasLocations判断有资料，却只显示activeRoots.length，产生“已管理0个位置”。这会让已拖入并单独授权文件的用户误以为授权失败。现在直接使用同一个overview快照，分别显示有效授权目录数量与独立授权文件数量，按仅文件、仅目录、混合、空范围显示；扫描时保留扫描指示并显示真实数量。暂停目录仍保留授权，已撤权目录不计入；失联文件仍有活跃单文件授权，不能因暂时不可打开而从授权数量中减去。

中英文均按当前语言显示，英文处理单复数。未增加provider、store、请求、持久数据、统计接口或额外授权；Rust仍为事实源。设置单文件卡片保留原有名称/路径，用现有时间线短文案区分“原件暂不可用”和“身份待确认”，正常文件不添加额外状态说明。未新增修复流程或视觉区块。

新增六组双语组合回归与一项设置状态回归，共107 UI/API测试。覆盖空、仅文件、仅目录含暂停/撤权、混合、扫描、仅撤权，以及失联/身份待确认/正常文件与切换语言不重做授权。完整检查及纽约时区执行结果见ACCEPTANCE。

开发视觉夹具新增scope=files-only，合成三个独立文件：正常长名/超长单段路径、失联、身份待确认。实际通过CUA操作Chrome原生界面检查中文100%摘要、英文200%摘要和设置长路径/状态；最后恢复中文100%。页面持续标记“合成资料、不连接原生后端”，不是WorkTwill原生IPC或授权验收。浏览器访问host不可用时使用Chrome原生AX/截图读取夹具，没有绕过WorkTwill应用访问拒绝。

Root定位仍未生产实现，独立实施计划见[ROOT_LOCATOR_IMPLEMENTATION_PLAN](../research/ROOT_LOCATOR_IMPLEMENTATION_PLAN.md)。那份研究说明下一轮必须整体接入的授权、扫描、暂停、恢复、监听与原生边界，不将一个表或Bookmark解析登记为完成。
