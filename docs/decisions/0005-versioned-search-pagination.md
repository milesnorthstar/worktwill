# 0005：完整搜索使用版本化游标

日期：2026-11-20。状态：迭代006已实施；原生IPC及渲染验收仍待执行。

原实现接受任意offset，前端收到后才核对版本。本轮将一致性检查推进到Rust：第一页offset=0且不带cursor；有后续页时返回`next_cursor`。后续请求必须原样回传游标并使用其next_offset。Rust在同一读事务中核对协议版本1、Store session、permission_version、revision、分页偏移及规范化查询条件；缺失或不匹配返回`stale_cursor`，不执行后续候选读取，不伪装空结果。

查询条件包括NFC/lowercase/trim后的关键词、工作区、类型、排序、修改时间半开区间和规范化字面路径/网址前缀。请求序号不属于条件，续页可以使用新的request_id。每页100项，最后一页不返回游标。每次请求的候选、资源详情、版本和后续游标属于同一SQLite读取快照，快速搜索也采用同一读取事务。SQLite运行中取消及quick/page会话隔离保持不变。

React保存最近一次有效响应的后续游标，按后端返回的next_offset加载。仅后续页`stale_cursor`触发清掉旧页、游标和选择并重读首页；首页失败明确报错，不循环重试。请求序号检查发生在写游标和处理失效之前，旧分页不能污染新的查询。变更通知仍立即隐藏旧资料；响应仍核对当前权限版本。

这里的游标是客户端回传的版本化描述，用于一致性检查，不是签名凭证，也不充当授权。SQL每页独立过滤当前授权、范围与输入条件。它不持有跨请求的数据库事务，不承诺跨写入保留旧快照；数据版本变化后从首页重读。内部仍是OFFSET分页，深分页成本及原生可见时延须另验，没有增加有增长风险的服务端游标登记表。

回归覆盖三种排序的完整三页链、规范化等价条件、所有条件维度和版本/偏移变化、缺游标、撤权、重启、重复恢复、实际独立连接并发提交，以及前端一次重读与旧响应隔离。性能和交付记录见[验收记录](../ACCEPTANCE.md)。时间线与普通资源列表的分页协议未在本决定中改动，仍按各自版本保护和验收边界推进。
