# 0033：新授权与恢复位置目录的有界优先扫描

日期：2026-11-20；迭代036。

## 实测问题

035在大目录扫描期间，通过原生选择器授权一个全新的两文件目录。后续观察仍为idle/scanned0，文件尚未收录；pick_root只合并到全量扫描dirty，首次授权需要等前面的目录。

036首阶段增加指定目录队列，首次授权小目录在确认后65ms生成发现记录，约0.76秒后界面显示完成。但整目录移位后的原生验收又暴露后续链路：Bookmark已找到新目录、原root UUID/identity和别名前缀保留，资源仍留在旧路径等待全量枚举。权限判断正确地隐藏了旧路径，界面显示匿名占位，不能用重新指向代替自动恢复通过。

## 实现与代价

原生Runtime新增至多16个待处理root UUID的FIFO去重队列；工作标记与出入队在同一Mutex内更新，退出时不遗漏新请求。最多一个指定目录任务与原全量任务并行，另保留既有单个有界通知刷新任务。不为每个目录创建线程。队列满时仍交由全量dirty核对，不扩大授权或丢弃业务资料。

新授权、恢复扫描、包含/排除目录复用指定root入口；不再因为修改一个目录就主动重扫所有无关目录。用户显式全量重新扫描、未知文件系统通知及既有协调保持。

Core保留scan_all原入口，并提供位置准备完成、开始全量root循环之前的通知。该时点不持有状态/数据库锁，Runtime可把有效、未暂停的idle目录送入同一队列；idle覆盖新授权及位置已恢复但文件路径尚未更新的目录，也覆盖重启中断后的待扫描状态。watcher发现活跃目录位置恢复时同样指定扫描；暂停目录保留原已知映射核对流程，不用扫描新增文件替代。

所有枚举仍调用Store::scan_root，复用当前授权/排除/物理身份、generation、恢复epoch和批次写锁。同根任务偶遇时由已有generation取消过期批次，可能产生少量额外工作；没有绕过目录有效性或用Bookmark路径直接继承身份。代价是枚举并发上限由1增加到2，长期资源预算仍需更多负载实测。
