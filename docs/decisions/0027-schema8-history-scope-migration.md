# 0027：schema8 补齐历史范围迁移与首次读取失败状态

日期：2026-11-20。状态：已实现并通过 Core/组件检查，实际应用库迁移及新包原生复验待执行。

## 事实与影响

重启客户端后，Computer-Use 曾实际读到 release WorkTwill 首页：显示本地数据操作失败、持续读取与首次空态。只读检查实际应用库确认 `user_version=7`，`activity_root_scopes` 仍为四列，查询 `retired_location_valid` 报缺列。此前在同一个 schema7 内追加该列却未提供版本升级，是本次读取失败的原因。它与此前原生应用访问拒绝是两个问题。

事实源是 SQLite；`activity_origin` 共用历史授权谓词由 overview、时间线明细和日历消费。React 不能通过隐藏错误、清空库或新建第二份数据解决。迁移前已用只读源连接执行 SQLite Online Backup，备份留在批准临时目录，未复制进仓库；这不是原生备份界面验收。

## 决定

- `migrations::VERSION` 升至8。v7→v8 在一个 Immediate 事务内检查既有四列、检测目标列、必要时 ALTER/更新，最后推进版本。其他缺失结构继续报错，不普遍补造损坏表。
- 四列旧库缺少身份退休时位置资格的证据，既有 scope 新列全部置0，防止已移出或排除的旧对象借旧目录复活历史。当前仍存在的同 identity 对象继续按当前权限读取历史；新观察默认1，实际退休时由已有逻辑冻结当时资格。
- 已有五列的 v7 库保留原0/1值，只推进版本。不得把已持久化的拒绝改为允许。
- 不改资源 UUID、关系、收藏、观察名称/来源或 DTO；恢复仍在暂存库迁移，源备份字节保持不变，恢复后重新授权。
- React 复用现有 overview/resources 读取状态。初始 overview 未就绪且读取已结束时显示短失败文案与「重新加载 / Try again」，结束 aria-busy；重试清除读取错误并重用原 reload，不触发重新扫描。已有资料上的普通操作错误不冒充初始读取失败。

主要代价：缺证据的旧退休对象可能减少可见历史；不根据当前路径猜测当年权限。未来若需恢复，必须有独立可信证据，不能将迁移默认值改为1。

## 验证与边界

新增5项真实旧版DDL迁移/恢复回归，覆盖四列与五列、当前/退休对象、关系收藏与来源保留、新capture/retire、源备份不变，以及触发器故障下 ALTER/数据/版本一起回滚并重试。既有逐表逐列损坏备份拒绝矩阵保留；新增3项首次读取失败/重试/普通操作失败组件回归。
