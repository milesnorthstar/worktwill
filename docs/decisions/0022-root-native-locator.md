# 0022：目录身份锚点与已有引用的位置恢复

日期：2026-11-20。状态：迭代024，macOS普通Bookmark与Core接入；完整原生窗口和发行验收单列。

整个管理目录改名或同卷移动后，原有路径不再足以定位其中的工作区引用。024为新授权目录增加私有物理身份锚点，复用普通NSURL Bookmark；不按字符串前缀批改资源路径，不新增隐式单文件授权。Rust仍拥有UUID、权限、位置和持久关系，React只显示必要的定位状态。

schema v6增加root_locators(root_id PK/FK CASCADE,identity,bookmark nullable BLOB,valid CHECK 0/1)和root_aliases(root_id FK CASCADE,path,复合PK)。active表达用户授权意图，valid表达当前目录路径是否仍是原对象。旧库没有可核对的历史目录身份：migration只建空表，旧root标legacy并沿用已披露路径语义，不stat追认；用户明确重选后才建立锚点。恢复前校验新表全部必要列，恢复后撤销root/file授权并清valid，定位数据不能复活权限。

显式grant_root在gate及SQLite写事务之外创建普通Bookmark，提交前复核目录类型、canonical路径及物理身份。同identity的明确重选复用root UUID及相对排除；新路径另属其他root时明确冲突。不同identity的明确重选清除旧aliases。Bookmark不是security-scoped凭据，也不代表跨卷、云盘或签名沙盒权限。

Store::open只对已有锚点做原路径metadata核验，不调用Foundation、不枚举目录。正常原目录保持可见；丢失、替代或类型变化时，valid、generation和permission/revision同事务变更。搜索、日历及分页仍使用这些正式版本失效；查询不为每一结果新增文件系统读取。

恢复先取root/path/identity/BLOB/valid/generation/p/r快照，在锁外解析候选，再于短事务CAS重核快照、active及实际目录身份。成功同事务保存旧路径alias、写新路径/Bookmark/valid、递增generation及权限/revision。失败状态由前一步真实提交；没有在随后返回Err的事务里假写valid0。单根定位失败允许其他根完成后明确报告；过时修复、重选或撤权后的错误丢弃，数据库/锁错误及时失败。

aliases只构造候选，不进入授权条件。使用Path::strip_prefix、join、canonicalize，再核当前root/exclusion和原文件identity。未暂停根沿正式扫描复用资源UUID；暂停根按稳定resource_id seek分批核对数据库已知映射，不枚举新增文件。普通移动不新增首次发现，也不伪造正文修改；真实mtime/size变化沿既有事件语义。旧路径已不满足VISIBLE的工作区引用可按UUID内部读取候选事实，但最终提交仍须当前有效授权。

私有RecoveryGuard只复用既有ingest提交路径。FileRecovery要求原资源、活跃file grant、原file Bookmark及版本；RootRecovery要求原资源/file_roots、原root/anchor/path/generation、有效当前scope及版本。入口本身强制候选等于guard的原文件identity；Root不提供updated_bookmark，不能把root BLOB写进file_locators。独立file locator失败时仍可尝试有效root authority，错误不扩大授权。

有效scope同时接入VISIBLE、path_allowed、导入/relink归属，以及扫描setup、有效检查、commit和finalize。扫描取消后按当前代次收尾，不永久running，不让旧收尾覆盖新扫描；restore epoch继续防止备份generation ABA。另一失效root的陈旧归属不能保护missing。仍有独立file grant时由其复验维护状态，root排除扫描不能覆盖那份有效授权的available；删除后独立复验仍正确标missing。锁顺序仍为catalog_write→gate.read→IMMEDIATE；Foundation不在gate或SQLite写锁内执行。

Watcher只监可用/legacy且未暂停根，新位置替换旧注册。启动、重新扫描、打开旧引用均有恢复入口；后台对暂停/空监听集每30秒核对，失败退避至最多300秒，同一错误不反复提示，明确重试或重新选择会重试监听。恢复成功后正式扫描会核对未暂停文件及暂停已有映射。这些原生事件接线须与实际窗口/系统监听验收区分。

前端Root增加location_status(legacy/available/unavailable)，不暴露identity或Bookmark。设置状态按撤权、定位状态、暂停、扫描结果展示；定位失效不被“已暂停”掩盖。legacy仍可扫描，首页和搜索的索引提示遵循同一正式规则。沿用添加管理位置的原生重选入口，无第二套权限store。

实际测试发现普通目录Bookmark在旧路径被新目录占用时可能回退到新对象。此时必须拒绝身份继承并保持引用；明确重选原目录后可按原identity复用root。不能把“有Bookmark”写成这一组合必定自动恢复。024不解决Document ID不可用、物理身份变化的Office安全保存、跨卷/云目录或Windows；Core重开不等于WorkTwill进程和窗口重启。原始检查、目录API、规模及交付证据见ACCEPTANCE中的024记录。
