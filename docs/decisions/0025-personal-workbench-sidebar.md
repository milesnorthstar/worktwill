# 0025：个人工作台首页与左侧主导航

日期：2026-11-20。状态：用户明确纠正，纳入迭代026；最终检查及候选包构建结果另记，不由本决定登记通过。

用户要求动态优先呈现文件变化、采用日历与时间线后，003曾将整体界面调整为顶部主导航并默认进入动态。用户本轮明确纠正：动态重要不表示它是默认首页，参考图只用于动态页内部；应用保留左侧导航、右侧主内容，个人工作台为默认首项。这一决定替代003的上述布局取舍，旧迭代日志与ADR保持历史内容。

左侧主入口依次为个人工作台、工作区、动态、所有文件和收藏，管理位置与设置保留明确入口。启动默认使用 `home`，品牌返回个人工作台；所有文件使用单独的 `files` 视图，收藏使用该视图的 `favorites` 模式及独立导航按钮，不再以修改首页模式代替对应入口。搜索结果返回时保留来源视图、工作区、分类与收藏模式。

个人工作台复用既有资源查询、资料列表、最近修改和最近使用交互，不增加平行的资源状态、查询协议或持久表。首页工作区卡片来自当前概览顺序的前3项，以原工作区UUID进入；卡片及列表继续复用已有拖入、选择、关联和打开能力，资源UUID、授权与Rust事实源保持原有归属。没有上次工作区的事实来源，不增加或显示伪造的访问历史；空列表不填充示例资料。侧栏工作区列表不再截断为12项，利用原滚动容器保留全部UUID拖放目标；授权范围未读取完成时显示既有双语读取状态，不提前判为空库。

首次空库以「添加管理位置」为主要操作，沿用既有范围就绪判断、常用位置建议和原生选择确认；确认前不授权、不扫描。单文件和网页入口继续保留，不要求用户先创建工作区才能找文件。UI加载期间不能提前将尚未读取的授权范围判为空库。

全局搜索常驻右侧主内容顶部，保留 `⌘K/Ctrl+K`、原位下拉与完整结果页。日历、按日时间线、局部筛选和快速返回仅位于动态页面内部；不以动态局部面板替换其他页面的全局导航，也不照搬参考图为整体应用外壳。

可用宽度不足时，左侧保留主导航图标栏及名称标识、当前页语义；工作区快捷列表可以收起，工作区主入口仍可达。固定侧栏采用 `overflow-y: auto`，主导航与底部设置不能被矮窗口或放大裁掉。右侧内容继续使用既有列表窗口、分页与页面滚动，不以布局变更取消既有性能要求。

代价是首页、所有文件和收藏需要明确区分导航与搜索返回上下文；通过App现有视图、模式及请求状态管理，不另建store或记录假历史。026已测的历史授权CASE优化继续保留，本决定不改变schema7、历史可见性、授权或U8门槛。

本轮检查需覆盖默认首页、前3真实工作区与排序、空库主要授权入口、所有文件和收藏的独立入口、搜索返回来源、动态内日历、中英长名称、窄宽图标栏及矮窗口侧栏滚动。组件、浏览器夹具、原生窗口与候选包构建分别记录；旧026检查、文档更新和原型均不能替代新布局验收。根目录原型与 `prototype-b/` 保持只读，正式实现仅在 `desktop/`。
