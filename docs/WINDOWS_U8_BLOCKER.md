# Windows U8 保存连续性阻塞记录（历史及当前剩余项）

当前更新：用户已批准显式NTFS目录追踪和明确替换语义，PRD/ARCHITECTURE已同步。正式服务与continuity原生候选已完成目标WPS运行中及退出期间Ctrl+S恢复、双区/收藏/recent验证；不再等待相同产品决策。临时替换源先收录的UUID冲突继续保守拒绝，真实精确时序、跨日/Word及其他验收矩阵仍未关闭。新证据与制品见[验收记录](WINDOWS_V1_ACCEPTANCE.md)末尾。以下内容是策略批准之前的失败与选择记录，不能当作当前禁止规则。

2026-11-21，本机 WPS 12.1.0.29690 的实际 Ctrl+S 保存已复现：正文标记落盘，物理 File ID 改变，原资源变为 identity_unconfirmed，新对象取得另一 UUID；原收藏和 A/B 工作区关系没有自动延续。独立 COM 夹具也复现，注册表确认该 COM 是 WPS，不能当作 Microsoft Word 结果。

当前候选的工程检查通过，不满足完整 Windows V1 的 U8。候选、摘要、测试日志和实际流程见 [Windows 验收记录](WINDOWS_V1_ACCEPTANCE.md)，失败原始状态见 [正式库快照](validation/2026-11-21-windows-wps-native-save-failed.json)。

## 当前证据限制

- 失败 DOCX 没有既存 NTFS Object ID，见 [只读查询](validation/2026-11-21-windows-wps-objectid.log)。因此，补接查询已有 Object ID 的实现不能解决这个样本。
- 相同路径、相同创建时间及保存前后的目录通知都不足以区分编辑器安全保存与另一个对象替代原路径。不能仅凭这些信息自动继承资源关系和单文件授权。
- 正文、DOCX 内部属性、文件名或内容哈希可被复制，不能直接作为唯一身份。尚未证明有可用的 WPS 文档延续标识；不得登记为已支持。
- 不能为通过验收而调用创建 Object ID、写 ADS/隐藏标记，或放宽现有身份和授权要求。架构的 Windows 身份章节及当前 AGENTS.md 明确限制了这些行为。
- 人工重新指向是现有保守恢复流程，不等于 U8 要求的日常保存自动延续。记事本同 File ID 的保存通过，也不能覆盖本次 WPS 失败。
