# 临时替换源已有UUID：待审阅的具体决定

2026-11-21。状态：**提案，未批准、未实现**。它不改变已批准的Object ID追踪、明确替换延续、旧单文件授权失效等规则。

## 已验证的问题

正式受控测试先扫描替换源B，再ReplaceFile覆盖已收藏/收纳的A。创建时间不同和相同两组都检测到卷+File ID竞争，拒绝自动续接；扫描、通知、导入、打开四入口都保留A/B UUID和原绑定，不写历史。真实WPS不共享删除探针捕获tmp先入库，但干预造成Object ID丢失；暂停探针保留标记但未收录tmp。这些结果不能推定正常WPS自然时序已通过。

本轮另外修复：冲突旧单文件grant曾使全量扫描提前退出，影响无关目录；现在完成其他文件/目录后仍报告原冲突。15项连续性、workspace200 Rust及严格clippy通过。该修复不消解A/B竞争。

## 可选方式及代价

| 方式 | 行为 | 代价与边界 |
|---|---|---|
| 保持现规则 | A/B冲突保留，用户走现有明确重新指向/确认合并 | 安全语义已实现，但该时序需要人工修复，不能算U8自动通过 |
| 所有新发现先暂存 | 自动扫描/通知先记候选观察，稳定后才建立正式UUID；显式导入仍立即建正式UUID | 可减少毫秒级临时源入库，不保证稳定等待后仍不会被替换；影响发现时延、历史首次发现时间、恢复与候选积压，需要独立设计/测量。不能把时间窗当文档身份依据，也不能处理已经存在的B |
| 显式用户批准一次冲突处置 | 展示A/B名称、当前可访问性、收藏、工作区与单文件授权；用户确认后用事务保留A、处理B并留审计 | 可复用现有人工修复方向，但仍属人工恢复，不算U8自动通过。不同创建时间下B旧identity与现对象不完全相同，不能绕过影响快照 |
| 新增受约束的自动“扫描观察被替换”语义 | 仅B全部来自自动发现、无独立授权/收藏/工作区/打开/人工编辑且当前独立对象已不存在时，A按已批准锚点证据延续；B UUID和原观察永久保留为明确的历史状态，不删除/合并关系，不将B旧事件改写给A | 这是新增产品规则：即使保留UUID，也改变纯扫描记录的当前/历史语义，未经批准不能实施。需要迁移、DTO、UI历史状态、历史授权、并发CAS、恢复、搜索和版本一致性，及源自然时序验证 |

建议先选择“所有新发现先暂存”作为减少暂态入库的技术方向，同时**保持所有已有正式UUID冲突拒绝**；这只能降低冲突发生，不可据此宣称关闭已有UUID冲突关口。若要求此顺序也自动取回，则必须批准最后一种记录生命周期语义，或另给明确可实现的处置规则。

## 如果批准新增扫描历史状态，实施前必须固定的契约

1. B不是凭“无收藏”判定；须持久证明仅自动发现来源，所有操作前后复验无独立用户意图。当前数据库没有足够来源证据，不能追溯猜测旧B。
2. A锚点、卷、目录身份、当前物理快照及绑定版本仍必须满足现有证明；B失联不单独证明A连续性。没有Object ID的干预样本仍拒绝。
3. 保留A/B两个UUID、原始活动identity、原始首次发现观察及完整处置审计；历史可见性独立按原授权判断。
4. 冲突期间任何收藏、打开、加入工作区、独立授权或人工变更都取消自动资格；有用户关系的B永远要求显式确认。
5. 所有入口事务内比较A/B快照、权限和恢复代次；绑定/旧grant/根归属/历史/投影/版本同事务，注入失败完整回滚，打开前继续复验。
6. 用户必须能看到B为何成为历史观察、A凭何延续；不把追踪同意当作任意资源合并授权。

以上是供审阅的具体后续方案，不是功能完成证明。当前目标仍需原生跨日、规模可见性能/中断和其余窗口/DPI等独立关口；任何本提案选择都不默许取消它们。
