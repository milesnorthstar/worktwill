# WorkTwill V1 产品审核：三 Agent 对抗复核结论

日期：2026-11-21。复核对象：[原产品审核](WorkTwill_V1_产品审查与整改方案.md)。

## 1. 结论

**原审核的大方向正确，但不能直接整包变成研发任务。** 应采纳去噪、收藏专页、首页突出取回、搜索结果可判断这四条方向；修正“先删所有文件，再补筛选承接”的顺序，区分已有能力与新增需求，并补齐权限、跨日保存取回及完整拖拽目标的验收。

这是一份改进建议，不是对现行 PRD 的覆盖，也不表示用户已经批准其中的页面删除或范围新增。

本轮三个独立 agent 分别负责：产品定位与信息架构、用户任务与交互闭环、数据语义与信任及交付优先级。先独立评估，再相互质询，最后由主 agent 对照六张原图及正式源码核查并汇总。没有修改产品代码、现行 PRD 或原审核；没有运行应用、测试或原生验收。文中源码事实说明实现路径，不能证明运行表现已经通过。

## 2. 逐项采纳意见

| 原审核建议 | 复核结论 | 实施前应修正或补充 |
|---|---|---|
| 默认结果过滤 `.DS_Store` 等工件 | 采纳，优先治理 | 区分自动收录、默认推荐、显式收藏/关联与授权；旧库已有噪声也要治理，不能只影响新扫描 |
| 收藏页去掉通用四 Tab | 采纳 | 收藏仍需打开、定位、取消收藏、批量加入工作区；不为换页面改变关系模型 |
| 首页优先帮助用户继续工作 | 采纳并修正表述 | 明确分开“从 WorkTwill 打开”和“最近修改”；没有打开记录时不能伪造使用历史 |
| 删除“所有文件”一级入口及独立页面 | 条件采纳 | 不记名称的取回和批量收纳必须有等价、可发现的承接；承接与删除同批，未完成前保留现入口 |
| 时间线去噪、降低重复卡片密度 | 采纳方向 | 先看不同事件与资源分布；五分钟只是候选窗口；保留真实事件来源和时间，不重写历史 |
| 搜索解释命中字段、改善长路径识别 | 采纳 | 展示真实支持的字段；不暗示全文搜索。先补命中依据和元信息，再考虑更多视觉形式 |
| 侧栏只显示固定或最近工作区 | 本轮后置 | 现侧栏是全部工作区的拖入目标；缩减后必须仍可向任意目标拖入 |
| 最近访问排序、工作区固定、收藏时间 | 单列后续增量 | 需要新增持久事实或明确规则，不能视作纯布局精简；不拿现有手动顺序伪装访问历史 |
| 增加可用预览 | 从本轮必做项移除 | V1 不内嵌 Office/PDF/网页正文预览；先用类型、元信息、完整路径及系统定位帮助判断 |
| 把筛选、分组、来源区分列为新能力 | 改为保留并补差距 | 当前已存在其中多项，不能重建一套或把旧实现重新记为新增成果 |
| 暂保留收藏、动态一级入口 | 采纳为当前最小变更 | 使用价值与竞争优势仍待真实任务验证，不因“看起来重复”继续横向砍入口 |

## 3. 最重要的六处修正

### 3.1 去掉重复容器，不等于去掉无名称查找任务

原审核 §0、§5 把删“所有文件”列为 P0 退出条件，日期/位置等筛选承接却放到 P1。当前 PRD 明确保留该入口及全部资料能力（[PRD §3.2](../PRD.md)，第 93、103、107、131 行）。这应记录为提议变更。

更实质的问题是：已知名称的搜索不能自动代替“不记文件名，只记得昨天或所在项目”的查找。

- 搜索弹层空词只显示输入提示，且仅有结果时提供完整结果入口：`desktop/src/workbench/components.tsx:36,52`。
- 前端空词不查询：`desktop/src/App.tsx:185`。
- 完整搜索后端明确拒绝空词：`crates/worktwill-core/src/search.rs:288–296`。
- 现有类型筛选是文件/网页/工作区，不等于已有 PDF/DOCX 等格式筛选；路径前缀输入也不等于目录浏览。

**建议产品约束**：无名称取回、最近资料深入查看、批量加入工作区不能丢失。候选可以是复用资源浏览，或提供条件检索，但具体改哪条查询链需实施时追踪，不在本轮预定为空查询改造。

这不要求再造一个同名或异名总表页。去重的对象是各页无差别复制的四 Tab 容器；独立任务是否需要列表应由任务决定。日常取回也不应埋到管理设置里。

### 3.2 去噪必须保住用户明确保存的资料

当前默认自动扫描规则跳过 `.git`、`node_modules`、`.cache` 和应用数据目录，没有针对 `.DS_Store` 的文件名过滤，源码与截图一致：`crates/worktwill-core/src/catalog.rs:40–66`。去噪确有依据。

但原审核“统一用户可见过滤层”需要更精确的职责：

| 规则 | 含义 | 不可混淆的边界 |
|---|---|---|
| 授权与身份校验 | 是否有权展示、访问，以及是否正确原件 | 硬门槛；任何高级显示开关不得绕过 |
| 用户配置的排除范围 | 用户明确不想自动索引哪些位置 | 按现行授权/排除契约执行，不能当普通推荐降权 |
| 系统工件质量策略 | 哪些自动发现项不值得默认推荐、制造动态 | 不等于撤权、删资源或删关联 |
| 显式收藏/工作区关系 | 用户明确保存的价值意图 | 不能因默认去噪静默丢失，仍受当前授权约束 |

单独授权只代表访问许可，不必强制进入推荐；它在授权管理中的记录应保持可见。`.env` 等有意义文件不能因点号前缀被统统排除。

必须处理已入库工件在默认列表、旧动态、日历计数和快速返回中的表现。只过滤新扫描，旧噪声会继续存在；只在前端拿到一页后过滤，会产生空页、漏项及计数不一致。采用一致规则不意味着所有页面共用完全相同的可见条件。

原报告建议的“高级显示系统文件”也是待决定的增量，不是解决去噪所必需的新设置。

### 3.3 现有时间线语义已区分，问题应定位到可读性与事件密度

原审核 T03 提醒来源诚实是正确的，但同卡出现“最后修改”和“应用发现”并不证明底层混用了字段：

- 首次发现与修改分别记事件，重复/重叠扫描在没有变化时不重复记账：`catalog.rs:413–425`。
- 首次发现始终用发现时间，仅修改事件可切换到 mtime：`timeline.rs:156–162`。
- 当前界面已解释时间维度，并显示事件来源和双时间：`desktop/src/timeline/ActivityTimeline.tsx:211,215,229`。

因此应先解释默认主时间、把次要时间收为详情，核查重复来源；不是重建事件模型。截图中的 81,168 条记录能证明总量大，不能证明重扫重复或统计错误。

若增加短窗口聚合：以展示/读取模型表达，不破坏原始 kind、观察时间、mtime 和来源；不同资源、不同类型不错误合并。窗口需考虑连续保存、跨日、跨分页和不同时间模式。当前时间线按每页最多 100 事件读取，日历按事件计数（`timeline.rs:253–307`），所以必须明确“组数”和“事件次数”，不能出现列表两组、日历却不解释地声称两次修改。

**“从 WorkTwill 打开”仍只表示系统接受请求且对象复验通过，不证明用户阅读或默认软件已完成加载。** 现行实现已有这条边界：`src-tauri/src/main.rs:313–335`；`PRD.md:220`。

### 3.4 首页不能换成另一种大杂烩

“继续工作”优先于工作区卡片有合理依据。当前卡片在通用资料列表之前（`App.tsx:327,335`），首屏的确难看到有用资料。

但原审核推荐版式同时塞入继续工作、最近动态、常用工作区、收藏捷径，可能重现重复。建议首轮只突出两类有事实的取回资料：应用内打开、最近修改；保留少量工作区入口。动态/收藏摘要只有能提供独立价值时再加。

首次导入历史目录时，mtime 新不等于用户刚工作过；没有打开记录时应据实展示。当前工作区卡片只是现有顺序前 3 项，不能改名“最近访问”。现行架构明确不将排序伪装为访问历史（`ARCHITECTURE.md:65`）；Workspace DTO 无访问时间，Resource 收藏是布尔状态（`model.rs:80–96`）。

### 3.5 拖拽、添加网页及批量操作不能因视觉收敛而失去入口

常驻投放条可以收敛，但任意工作区仍必须成为可达目标。当前 PRD 明确保留全部真实侧栏目标（`PRD.md:102`）；源码逐项输出真实 UUID 目标（`App.tsx:308`）。

“只显示固定/最近工作区”“拖动时再显现目标”要一起回答：目标不在最近列表时如何找到，窄窗口能否滚动，原生 Finder 拖动是否同样可用，取消是否清除状态，键盘或点选能否完成等价任务。首轮保留完整目标列表，是更小的变更。

同理，收起全局“添加网页”前，确保用户无工作区也能保存网页；收藏页精简后保留批量加入已有/新工作区，不能只留下打开和取消收藏。

### 3.6 暂时失联、撤权、身份变化不能统一成“失效”

原审核 A14 只用移动/删除覆盖异常场景，不足以保护已有状态语义。

- 同一物理对象改名/移动：在已验证定位能力和当前授权范围内恢复，不能一概要求人工重连。
- 有授权但暂时找不到：保留名称、关系和不可用提示。
- 最后一份授权撤销：全局搜索、最近、收藏、动态隐藏名称路径，工作区匿名占位；仍有其他有效授权时继续可用。
- 同路径被另一物理对象占用：保留旧关系，身份不明时人工确认，不静默打开新对象。

这是现行 `PRD.md:229–237` 的既定行为，当前 `store.rs:292–296` 与 `components.tsx:79–97` 已区分全局入口和工作区占位。新 UI 必须保留这组差异；“跨页一致”应理解为遵守同一事实和规则，而不是各页显示相同信息。

| 最近工作区、固定、收藏时间 | 当前没有完整对应持久事实 | 独立评估需要，Rust 保持事实源，不用前端缓存伪造 |

## 5. 建议的实施顺序

不沿用“先删页、再补承接”的顺序，也不让界面优化替代已有工程收尾。

1. **先修已明确的质量问题**：系统工件默认噪声、收藏重复 Tab、命中依据与长路径判断；保留原授权和关系。
2. **做一次有边界的页面调整**：首页突出有来源的取回资料，收敛不相关按钮；删除所有文件若获采纳，必须连同无名称取回、深入浏览及批量操作承接一起交付。
3. **按真实分布治理动态**：先看首次大目录导入、普通办公连续保存和不变重扫，再决定聚合窗口与默认类型；不扩展成审计、版本历史或监控日志产品。
4. **再评估增量**：固定/访问排序、收藏时间、工作区列表切换、更细格式筛选等，根据使用结果单独排期。

工程底线继续执行现行 [PRD §9.0](../PRD.md) 和 [收尾清单](../docs/CURRENT_ENGINEERING_CHECKLIST.md)：先 Mac 核心闭环及独立交付，再 Windows 独立验收；外部拖入、保存重启后取回、权限与原件安全、真实搜索体验仍是关口。当前记录中修后 Finder 目标/授权矩阵仍未关闭，不能用“导航已删除”替代完成证明。签名、公证、完整备份覆盖矩阵及用户留存沿用既定阶段，不因本报告重新扩大前置范围。

## 6. 原审核应追加的验收

以下均是建议的验收条件，**本轮没有执行，不代表通过**。可变样本仅在已确认临时根中另建独立样本目录。

| ID | 场景 | 应检查的结果 |
|---|---|---|
| R01 | 不建工作区、不记文件名，只记得昨天或所在目录 | 仍有可发现路径取回资料，并可多选加入工作区；删入口前后任务不断路 |
| R02 | 首次授权包含多年旧文件的目录，无应用内打开记录 | 首批可用即能搜索；发现与修改来源清楚；不伪造最近使用或正在继续的工作 |
| R03 | 自动收录系统工件，随后对其中一项明确收藏或关联 | 默认推荐/普通动态去噪；显式关系不静默丢失；授权管理不因质量策略消失 |
| R04 | 旧库已有大量工件事件，过滤后继续翻页/切月 | 默认列表、日历、摘要、快速返回口径一致；无过滤后的假空页；不删业务关系 |
| R05 | 同资源连续修改，跨分页/跨日；中间夹一次打开与其他资源事件 | 聚合边界明确，事件来源不丢，不跨类型乱合并；组数与事件次数有解释 |
| R06 | 最后授权撤销、仍有其他授权、暂不可用、同路径换新对象 | 四种情况按既定规则分别展示；计数与搜索旧回包不泄露；不误连原件 |
| R07 | 50 个工作区，拖向非最近且初始不可见目标 | 目标可找到并命中正确 UUID；取消/重复/混合授权反馈准确；原件不变 |
| R08 | 无工作区保存网页；收藏两项后加入已有/新工作区 | 收起通用按钮和投放条后入口仍可达，批量能力仍在；网页离线可手填 |
| R09 | 同文件关联两区并收藏，外部日常保存，退出/重启后打开 | 打开正确原件，UUID/两区关系/收藏保持；需人工重连时不得记为自动延续成功 |
| R10 | 精确文件名与路径弱命中混合，夹同名文件/网页/工作区 | 排序可解释；高亮实际命中；同名明确选择；不暗示全文支持 |
| R11 | 搜索后进入工作区或操作关联，再返回；无结果、快速换词和取消 | 来源/查询/范围有清楚连续性，旧结果不覆盖，不误打开；无结果仍可检查授权范围 |
| R12 | 中英、最小原生窗口、鼠标及键盘完成核心操作 | 所有入口可达、焦点清楚、长路径可判断；原生打开/拖入需原生证据 |

保留原审核找 5–8 位陌生目标用户做任务观察的建议，但这只提供早期可用性线索，不足以证明留存、普遍偏好或市场差异化。记录真实任务成功率、完成时间、错开文件及提示次数；与 Finder/系统搜索及同类工具的效果比较放到试用阶段。

## 7. 对抗中实际修正的判断

- 产品方向 agent 起初把“空词加筛选”直接视为最小实现；任务流程 agent 依据后端空词拒绝与现有筛选边界质疑后，改为只固定任务要求，保留具体实现选择。
- 产品方向 agent 起初倾向把时间线聚合与差异化研究一起后置；信任 agent 指出时间回溯已属批准的 V1，修正为可用性治理应做，竞争优势仍待验证。
- 信任 agent 与流程 agent 进一步区分单独授权和收藏意图：前者是访问事实，不强制推荐；后者是明确保存意图，不能被去噪静默覆盖。
- 三方最终都支持条件精简入口，不支持先删再补；都不把新增预览、访问历史或统一隐藏规则当成本轮默认范围。

最终建议：**按修正版推进“资料质量与取回体验”，以任务成功和原件安全验收；页面减少只是可能的结果，不作为独立成功标准。**
