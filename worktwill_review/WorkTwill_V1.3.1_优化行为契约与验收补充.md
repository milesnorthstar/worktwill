日期：2026-11-21。状态：实施规范补充；本轮只审查、验证现状并编辑文档，没有修改产品源码。

保留已选定的三张UI参考图，不改变整体视觉方向。本文件承接 [V1.3开发、架构与产品审查](WorkTwill_V1.3_实施文档开发架构与产品审查.md)，固化已讨论的V1.3.1数据与搜索状态要求，新增搜索请求调度、资料打开交互和打开时页面稳定性的优化建议。新增交互方案是评审推荐，不冒充已经实施。

## 1. 本轮结论与证据

| 问题 | 核查结论 | 本版处理方向 |
|---|---|---|
| 搜索是否完全没有防抖 | 不是。快捷搜索已有40ms尾部防抖；完整结果页随输入立即发请求 | 补齐两种视图的统一调度规则，实测调参；不默认叠加节流 |
| 输入时为什么可能闪动 | 快捷搜索在防抖等待前就清空结果；完整页输入也会清页并发请求 | 区分输入草稿、有效请求与显示结果；保留必要结构，不展示可误操作的旧结果 |
| 单击选中、双击打开是否有冲突 | 当前双击资料名会先切换选择两次，再打开 | 推荐名称单击打开、复选框选择，移除文件/网页行尾的冗余打开箭头 |
| 打开时为什么可能闪动 | 打开链路包含全局catalog事件和run完成后的清空重读 | 按事件影响刷新，不因普通打开清空整页；保留权限/身份变化的强失效 |

- 完整页：`App.tsx:139–177`，query及筛选变化直接执行overview/searchPage，无文本防抖。

- 选择与打开：`desktop/src/workbench/components.tsx:84–95`，名称click调用toggle，行dblclick调用open，尾部ChevronRight也调用open。
- 清页：`App.tsx:84–90` 的reload清overview、page、selection、cursor和offset；catalog事件调用它，run成功后也调用它；activate打开使用run。

## 2. V1.3.1已有约定继续有效

| 事项 | 要求 |
|---|---|
| 便签一致性 | 当前文本版本提交后才能显示已保存；旧响应不得覆盖新草稿；重试不重复创建，删除不被迟到保存复活；退出失败与草稿恢复承诺明确 |
| 便签更新范围 | 使用独立的领域更新通道，不因正文自动保存刷新资源结果、清选择或失效无关搜索；仍使用现有Rust/SQLite事实源 |
| 空词搜索 | 可进入完整页，但不发送非法空词请求、不自动列全库；清空输入及时取消旧请求 |
| 最近打开 | 返回并显示真实opened时间，不用mtime替代；系统接受打开不等于用户阅读 |
| 图中控件 | 列出真实实现、调整与延期项；未实现的新窗口、总数、格式筛选或跳页不做假入口 |
| 小组件范围 | 伙伴和便签属于完整V1.3.1；P1表示实施顺序，不追溯为旧版工程收尾的新阻塞 |

数据库整体恢复或权限变化仍可使相关领域状态统一失效；“独立通道”不意味着绕开必要校验。

## 3. 搜索请求调度

### 3.1 用尾部防抖处理文本，不盲目叠加节流

用户输入立即显示在输入框，Rust查询在短暂输入停顿后执行。名称、路径前缀等可连续输入文本按此处理。快捷和完整搜索均适用，但保持独立请求通道和状态。

可先以 **80ms作为候选值**开展测量；这不是已经测得的最优值，也不是冻结参数。最终按真实输入、查询耗时与原生可见延迟调节，避免把常见的300–500ms防抖直接用于本地即时搜索。

搜索的输入至首批可见P95预算仍沿用项目现有目标，**必须包含防抖等待**，不只测数据库执行。不能为了少发请求，静默放宽总响应预算；中文1–2字仍必须可查，不增加最少两字等门槛。

不默认同时加防抖、节流、最大等待、重试和前端结果缓存。节流用于固定频率持续执行，容易查询到输入中的中间词；当前首先需要的是短尾部防抖及取消旧任务。

### 3.2 不同动作分别调度

| 动作 | 调度规则 |
|---|---|
| 连续输入查询词/路径前缀 | 更新草稿；停顿后提交最新快照，中间定时器取消 |
| 中文组字开始和过程中 | 不提交组字中间字符串；作废不再适用的旧意图 |
| 组字结束 | 对最终文本只安排一次正常查询；候选确认Enter不打开文件 |
| 点击类型、工作区范围、排序、日期 | 立即应用完整有效条件；取消与其冲突的文本定时器，不执行半新半旧条件 |
| 明确提交/进入完整页/点击历史项 | 取消待执行定时器，按明确提交的快照执行，避免先旧后新发两次 |
| 清空、Esc、离开页面 | 立即取消本通道等待及在途请求，不等待防抖结束 |
| 撤权/恢复数据库/身份变化 | 立即执行原安全失效流程，不做防抖或延后隐藏 |
| 加载更多 | 消费当前有效游标；防重复点击，不能用文本防抖代替分页校验 |

防抖只减少发送，不保证旧请求停止。现有quick/page两条取消lane、request_id、session、permission_version和分页revision检查继续保留。新输入到来时立即使旧响应失效，不等定时器触发后才更换有效意图；预期取消不显示为用户操作失败。

### 3.3 防抖不能制造新的闪动或误开

- 不在每次按键时卸载整个弹层/结果容器，不反复显示“空结果→加载→结果”。输入控件、布局和焦点保持稳定。
- 可以保留结果区域几何或上一次画面作为非交互的更新中状态；**旧条件结果不得继续默认高亮并被Enter打开**。无法保证时应明确取消其可操作性，而不是为了不闪允许打开旧目标。
- 短查询不必立刻闪一次大加载态；慢查询需有清楚但稳定的进度反馈。
- 数据或权限失效时不以“保留旧内容”绕过安全清除。不要把这种场景与普通文本请求合并处理。

## 4. 快捷搜索与完整搜索隔离

以下契约已经讨论确认，应成为独立验收：

> 完整页查“合同”，打开快捷搜索输入“招聘”，按Esc后，完整页仍为“合同”，保留有效筛选、排序、已加载结果、分页位置和滚动。只有明确选择“进入完整搜索”，才提交弹层词和兼容条件，形成新的查询。

快捷搜索只持有临时查找意图，修改它不提交完整页请求。选择类型或查看快捷结果也不修改来源页。点击文件/网页执行打开，点击工作区执行导航，不等于把快捷查询提交到完整页。

如果期间撤权或数据变化导致来源结果/游标失效，应保留“合同”及合法条件并重读，不能机械恢复旧元数据或旧游标。相同快照未失效时，不因为关闭弹层而无故刷新来源页。

两种交互复用Rust匹配、权限和资源操作，不另建第二套搜索；前端仍复用现有状态所有者，按职责区分草稿和已提交查询。

## 5. 资料选择与打开的产品建议

### 5.1 问题判断

“单击选中、双击打开”本身是常见文件管理器模式，并非必然错误；当前问题是名称click既代表批量选择，又位于dblclick打开链中，再叠加含义不清的尾部箭头。它与快捷搜索点击即打开不一致，双击过程也会让选中样式和批量操作条出现后撤回。

因此不建议仅增加一个双击延迟定时器。那会让每次单击都等系统双击窗口，仍未解决同一名称承担不同任务的问题。

### 5.2 推荐方案：打开与批量选择分开

| 区域 | 文件/网页 | 工作区命中 |
|---|---|---|
| 资料名称及其主要点击区 | 单击打开原件/网页 | 单击进入正确工作区 |
| 复选框 | 只负责勾选/取消，供批量关联等操作 | 不作为可加入另一工作区的文件勾选 |
| 行内无操作的留白 | 可定位焦点，不隐式开文件或切换批量勾选 | 同样避免隐藏副作用 |
| 收藏、定位、更多 | 只执行对应操作，不冒泡打开 | 仅提供该类型适用动作 |
| 文件/网页尾部ChevronRight | 移除这个冗余打开入口 | 工作区若保留方向提示，应明确表示进入工作区 |
| 键盘 | 焦点在名称时可打开；复选框用标准键盘切换；支持可见焦点 | 导航语义清楚 |

首页、快捷搜索、收藏、完整结果和工作区资料列表，尽量使用同一“点名称打开、勾选批量处理”的规则。不开启新详情页或预览功能。现有“单击名称选择、双击打开”的PRD和测试约定需要在采纳此方案后一起更新，不允许只删箭头而留下矛盾文案。

### 5.3 不引入重复打开或拖拽回归

- 用户双击名称，应归为一次打开意图，不能因为改成单击打开就启动默认应用两次；处理重复click/dblclick事件及在途请求，不能靠“通常加载慢”保证。
- 一次点击只发送一次打开请求；键盘长按也不得重复启动。在途同资源打开防重，结束后允许用户再次明确打开。
- 拖拽达到现有阈值后，松手不触发打开；复选框/收藏/定位不启动资源拖动。
- 保留已验证的原生Pointer拖动边界，不为改名称点击盲目删除现有preventDefault或300ms拖后click抑制。
- 不可用、撤权或身份不明资源不能借新点击区域绕过原生复验；明确显示状态及适用修复路径。

这是一项推荐交互变更，尚未修改代码。若后续选择继续采用桌面式单选/双击，也应去掉冗余箭头，区分焦点与批量勾选，并消除双击引发的可见勾选抖动；不要同时实现两套相互冲突的名称点击规则。

## 6. 打开时页面稳定性

### 6.1 当前链路与证据边界

```text
activate → run(api.open)
           ├─ Rust复验、系统打开、opened记账、catalog-changed
           │                                    └─ 前端reload清列表
           └─ run成功后再次reload清列表
```

双击的选择切换、以上清页重读，以及默认软件切换到前台，都是不同现象。合成实验已证明前两项中的事件顺序和列表消失，不能据此断定用户看到的全部闪动都由它们造成。原生复验需区分应用内列表闪白与系统正常窗口切换。

### 6.2 优化规则

- 普通打开不必先清空overview、当前资料和全部选择，再换成全页加载态。保留已验证且当前仍可见的行、滚动及焦点；必要数据后台更新并按稳定UUID替换。
- 识别打开产生的实际影响：最近打开排序/时间、活动计数、恢复后的路径等仍要更新，不能为不闪停止记账或不更新界面。
- 协调原生事件和命令完成后的更新，避免同一事实触发重复清页。不能简单删除所有catalog事件，因为打开失败前也可能已经提交定位更新。
- 会改变授权、身份、恢复epoch或可见范围的事件继续强失效；不得保留或恢复不该显示的名称路径。
- search revision改变导致旧cursor失效时，按既有规则重读，不能继续使用旧cursor。普通打开的内容保留与游标有效性分别处理，不为了保页放宽后端校验。
- 最近打开列表可能因真实使用改变顺序，应在有效响应提交时更新，而不是先变空；选中项只保留仍存在且允许操作的UUID，焦点/滚动按实际列表变化合理处理。
- 打开失败要明确反馈，并正确释放在途状态；系统已接受但活动未记账时，沿用现有准确提示，不静默自动再开一次。

这是刷新职责和查询失效的优化，不是加一个透明动画遮住清空过程。不得为此全面重构run、事件系统或持久层；先追踪每类操作需要的消费者，做最小正确调整。

## 7. 优先级与验收

请求正确性、组字、状态隔离、打开防重和权限边界按P0正确性要求；防抖时长和加载提示按实测调优。交互简化是待采纳的本轮产品建议；普通打开导致的列表清空作为本轮体验缺陷处理，原生视觉表现仍待验证。

| ID | 场景 | 通过条件 |
|---|---|---|
| OPT-01 | 一次防抖窗口内连续输入多个字符 | 只提交最后一份有效文本快照；在不同速度输入下记录实际请求数，不要求慢输入永远只有一次 |
| OPT-02 | 完整页输入、路径输入、类型/日期切换及明确提交 | 两种文本均调度；明确动作不重复发旧/新请求，不混条件 |
| OPT-03 | 中文连续组字并Enter确认候选 | 中间组字不查询、不误开；最终文本正常查，中文短词仍可用 |
| OPT-04 | 清空、Esc、换页、撤权时存在定时器和慢请求 | 及时取消，旧响应不能覆盖；撤权不等待防抖，预期取消不弹失败 |
| OPT-05 | 快捷弹层改词后按Enter | 不打开前一词留下的目标；输入框和结果布局不反复卸载 |
| OPT-06 | 合同完整页→招聘快捷搜→Esc/明确进入完整页 | 取消保留有效来源，明确进入才形成新查询；失效游标不复活 |
| OPT-07 | 名称单击、双击、键盘重复、尾部按钮 | 按采纳的统一规则执行；一次打开意图最多一次系统调用；无含糊冗余箭头 |
| OPT-08 | 勾选、收藏、定位、拖动并松手 | 不误开，批量关系正确，原生/内部拖入边界不退化 |
| OPT-09 | 当前已选择资料并滚动至后页，再打开一份 | 无无谓整页空白和重置；仍有效的选择/焦点合理保留，过期游标按规则处理 |
| OPT-10 | 打开导致定位更新、记账失败、撤权或对象变化 | 正确状态更新/提示，无越权旧内容，无自动重复启动 |
| OPT-11 | 正常及慢查询的原生输入至结果可见 | 统计包含防抖的端到端P50/P95/P99，沿用既有预算；不只报告Rust耗时 |

本轮只执行第1节所述现状实验，不将本表登记为已通过。原生打开、焦点切换和视觉闪动需使用批准临时目录中的合成文件验证，不拿真实办公文件反复试开；Mac和Windows分别记证据。
