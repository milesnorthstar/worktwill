# WorkTwill V1 综合对抗审查与产品整改裁决

更新：2026-11-21。状态：产品整改决策稿；包含已明确决定、推荐方案及后续验收条件。

## 1. 最终结论

**WorkTwill 应帮助用户找到资料、继续工作，并在需要时建立跨目录的工作区关系。当前整改同时处理页面职责、资料质量、搜索质量与首次使用价值，不以菜单数量或测试数量证明产品好用。**

本次明确修订此前结论：

1. **开发阶段直接删除「所有文件」一级入口与独立页面。** 不再暂留菜单，不等待新浏览系统建成后才删除；不把该页面改名为「资源库」重新放回一级导航。
2. **保留全局检索、资料访问和批量组织能力。** 删除界面不删除资源、索引、授权、收藏、工作区引用或源文件；也不要求本轮先建设复杂空关键词查询、目录树或高级分类系统。
3. **本轮必须评估搜索质量，根据结果决定是否修改排序。** 不预设已有四档排序足够好，也不预设必须新增降权算法。关键取回任务受阻时，修复进入本轮。
4. **数据质量与页面去重并列第一批。** 不先整理外壳、再处理充斥首页和动态的系统工件。
5. **首次使用验证实际收益。** 用户不创建工作区，也能在首批资料可用后找到并打开需要的文件，理解最近修改的用途。
6. **工程约束继续保留。** 原件只读、权限与身份校验、真实活动来源及跨日取回不因界面精简而放宽。

删除「所有文件」是用户已明确的产品决定，见[决定0037](../docs/decisions/0037-remove-all-files-page.md)。本文不再把该决定写成待确认问题。其余内容形成后续整改的推荐目标和验收规则，不代表功能已完成，也不等于现在继续修改代码。

## 2. 本次整合吸收与修正了什么

输入材料为[原产品审核](WorkTwill_V1_产品审查与整改方案.md)、[另一份三 Agent 审查汇总](WorkTwill_V1_三Agent对抗审查汇总.md)、[上一份三 Agent 复核](WorkTwill_V1_三Agent对抗复核结论.md)，以及用户在综合报告后的逐项反馈和最新删除决定。

| 议题 | 此前判断 | 本次裁决及理由 |
|---|---|---|
| 所有文件页面 | 本轮暂留，承接后再删 | 改为直接删除。用户已明确开发阶段取舍，不继续把现实现状当作长期信息架构依据 |
| 全局浏览 | 保护任务，但容易演变为删页前先建新系统 | 保留能力目标；当前利用已有资料、搜索和工作区路径，不把完善新浏览系统作为删除前置 |
| 搜索排序 | 显式搜索本轮保持现状 | 改为本轮评估、按证据修复。保持现状只是在没有证据时不盲改，不是整改原则 |
| 首次使用 | 主要检查状态真实 | 补充首次有效操作和用户理解；正确显示空态不能证明有价值 |
| 批次顺序 | A 呈现整理、B 质量契约 | 改为数据质量、页面去重、首页取回及搜索质量共同构成第一批目标；工程上仍可分别实现与验证 |
| 系统工件去噪 | 统一结果过滤 | 坚持按页面用途、事件来源和明确用户操作处理；主动搜索、收藏不被一刀切禁止 |
| 时间线 | 先去噪、再诊断是否聚合 | 保留；补充历史观察身份、分页和计数边界，不固定五分钟窗口 |
| 返回与键盘 | 容易笼统写成完整恢复 | 按具体动作验收；基本键盘、焦点、输入法随所改流程检查 |

三位 agent 的此前交叉审查提供风险识别和源码路径证据；它们没有完成真实办公用户任务研究。多份报告使用相同截图和实现，不能据此认定已有多轮独立产品验证。

## 3. 信息架构与页面职责

### 3.1 一级结构

```text
WorkTwill
├─ 个人工作台：继续打开资料、返回工作区
├─ 工作区：组织和关联文件与网页
├─ 动态：按时间找回有来源的资料变化
├─ 收藏：返回明确保存的重要资料
└─ 管理位置与设置：授权范围、索引健康和应用设置

全局固定入口：搜索框 / ⌘K / Ctrl+K
├─ 快速结果弹层
└─ 完整结果视图：已有筛选、排序、分页及批量操作
```

「所有文件」不再独占一级菜单，也不保留独立页面。搜索和资料浏览长期朝同一访问体系收敛；搜索不是只能输入关键词的最终产品定义，但当前不承诺已经具备无词条件检索。

### 3.2 各页面的整改要求

| 页面 | 核心任务 | 本轮方向 | 避免的结果 |
|---|---|---|---|
| 个人工作台 | 找回资料、返回工作区，继续手头的工作 | 有来源的最近资料优先，工作区仍容易返回；减少通用控制和整块重复内容 | 换成另一张巨型文件总表，或把动态、收藏、工作区卡片全部堆满首屏 |
| 工作区 | 围绕一件工作组织跨目录文件与网页 | 保留引用管理、多选、拖入、转移和打开 | 改成真实文件夹操作，或只剩少量常用目标可选 |
| 动态 | 回忆何时发生过哪些可确认变化 | 自动观察工件去噪，主次时间清楚；诊断后再定聚合 | 将文件系统通知当用户编辑审计，或抹掉真实应用操作 |
| 收藏 | 返回用户明确保存的资料 | 删除重复四 Tab，保留打开、定位、取消收藏和加入工作区 | 进入收藏后还能切成不相关通用页面，或去噪导致收藏静默消失 |
| 完整搜索结果 | 深入查找、判断和批量组织 | 保留并核查现有分组、筛选、排序、分页和选择 | 仅证明索引有目标，用户却必须反复猜词或翻很多页 |
| 管理位置与设置 | 控制范围、理解索引状态与错误 | 授权、排除、状态和必要重扫可找到 | 把日常资料查找埋在设置里 |

「首页现有资料筛选继续可用」是开发阶段的能力保留，不代表首页长期要复刻旧「所有文件」的完整容器。删除独立页面与首页后续优化可以分别实施；不为删除额外增加一个同类页面。

### 3.3 能力保留与真实限制

| 能力 | 删除后继续保留的路径 | 边界 |
|---|---|---|
| 按名称或路径找文件、按标题/URL找网页、找工作区 | 全局搜索及完整结果 | 不暗示全文、OCR或语义搜索 |
| 深入查找、筛选和加载更多 | 完整结果的既有条件、排序与分页 | 当前仍需关键词；文件/网页/工作区筛选不等于PDF/DOCX格式分类 |
| 最近资料访问 | 首页现有资料入口 | 不把首屏有限项目宣称为完整浏览能力 |
| 收藏取回 | 独立收藏页 | 继续遵守当前授权规则 |
| 批量组织 | 首页、收藏、工作区及完整结果的已有多选/关联路径 | 不改变真实磁盘位置 |
| 不记名称的旧资料查找 | 当前可利用已有列表、时间回顾及适用线索；长期补足统一浏览入口 | 删除后不再有独立总表页；无词条件检索尚未实现，不在验收中冒充已支持 |

**开发阶段接受取消重复页面带来的独立浏览入口变化，不接受删除底层业务数据或把缺失能力写为已完成。** 若真实任务证明无名称取回成为关键阻碍，应安排最小承接方案；不自动恢复旧一级页面，也不自动扩建复杂搜索系统。

## 4. 第一批同时治理资料质量与界面重复

### 4.1 默认去噪的产品规则

`.DS_Store`、`Thumbs.db`、经确认的 Office 临时锁文件等属于规则候选，须按文件特征和平台核对。不按隐藏属性、点号前缀、临时目录或文件类型泛化过滤，避免误伤 `.env`、配置及真实业务资料。

| 场景 | 默认行为 |
|---|---|
| 首页推荐、最近修改 | 不推荐已确认的系统工件 |
| 工件的自动首次发现/修改动态 | 默认不展示；日历及相关摘要使用同一质量口径 |
| 用户主动从 WorkTwill 打开、最近使用 | 保留规则允许显示的真实打开记录，不因工件分类静默改写行为 |
| 用户明确收藏或加入工作区 | 关系和取回路径保留，继续服从权限与身份规则 |
| 用户主动搜索 | 不因为系统工件分类直接禁止检索；排序是否优化由本轮质量评估决定 |
| 关联、移除和修复等应用操作 | 按现有分类保留必要事实，不将所有事件一并抹去 |
| 授权管理 | 保留授权事实；单独授权不等于必须进入推荐 |

搜索质量改进可以减少噪声干扰，但不能演变为“系统文件不可搜索”。也不能把默认降权、推荐过滤与撤销授权混为一谈。

### 4.2 工程边界

- 授权和身份是硬门槛，质量规则不得扩大权限或复活撤权元数据。
- 处理旧库已有工件，不能只改未来扫描。列表、日历、摘要和分页需定义一致口径，不在拿到一页后删行造成假空页。
- 去噪不删除源文件，不随意清理资源、收藏、关联和原始历史。
- 旧动态依据观察名称与来源判断，不拿重新指向后的当前名称重新解释过去；未知来源不补造。
- 当前已跳过的 `.git`、`node_modules` 等目录不因这次策略变成必须收录；搜索也不承诺能找到未入库资料。
- 不把高级开关、例外规则集合或新表结构作为默认解法，先复用现有职责与抽象。

## 5. 搜索：本轮评估，关键问题本轮修复

### 5.1 原则

**已有四档排序是实现事实，不是质量达标证明。** 本轮先建立任务样例和结果基线；若满足任务就保留，若关键目标被挤出可用结果或难以判断，就定位并修复。

当前名称全等、名称前缀、名称子串、仅路径命中已有优先级。名称命中的业务文件若被纯路径命中的数字文件压住，应先查候选选择、排序执行及展示是否符合规则，再考虑新排序。大量图片/视频是否低价值取决于任务，不能默认所有 Word 都比图片重要。

### 5.2 最小评估集

使用合成办公样例和经用户明确允许的真实任务；不擅自扫描业务目录，也不需要读取文件正文。每项先明确目标资源或可接受目标集合，再记录检索结果，避免事后挑选成功案例。

| 场景 | 核查重点 |
|---|---|
| 唯一精确名称 | 应在正确资源中快速确定目标，不能被较弱路径命中挤走 |
| 部分名称、前缀、中文1–2字与中英混合 | 召回、次序、易混目标和改词次数 |
| 仅父路径/URL命中 | 命中解释准确，数字文件名也能判断为何出现 |
| 同名不同目录、不同版本及网页/工作区同名 | 能区分原件，明确选择，不凭名称猜测打开 |
| 大量工件或非目标资料干扰 | 目标是否被挤出Top30；完整结果是否可达；用户是否因此放弃或误开 |
| 扫描中、条件切换、取消与撤权 | 不展示过时结果，不越权；已有可用资料仍可查 |
| 没有命中 | 不伪装为仍在扫描，能看懂支持范围并调整线索 |

至少记录：是否召回、目标位置、是否需进完整结果、改词次数、完成时间、误开和提示次数。核心测量是任务成功与判断成本；“完整列表中存在”只能证明可达。

### 5.3 何时需要本轮修复

- 唯一精确目标被更弱命中错误压住、授权结果错误或旧回包覆盖：按正确性缺陷修复。
- 代表性任务中目标虽被索引，却因排序、候选限制或展示长期难以找到：进入本轮整改，不能用“算法已有四档”结束评估。
- 用户缺少定位原件所需信息：补真实命中字段、可辨类型和完整位置查看。
- 当前能力边界外的语义/正文问题：明确不支持，不借搜索质量整改引入全文、向量或AI依赖。

修复可以发生在候选、排序、筛选或展示，不提前锁定某种降权算法。新方案需在同一任务集比较，并保留权限、中文短词和既有性能预算，不为相关性牺牲错误原件防护。

### 5.4 命中说明

首批准确说明名称、路径或URL等实际命中字段。若做高亮，正确映射规范化文本与原始显示文本，覆盖组合字符、大小写变化和emoji；无法可靠映射时不猜位置。弹层类别数字若仅代表当前返回条数，不表达为库中精确命中总数。

Rust继续拥有查询与跨端DTO事实源，必要变更从 `model.rs` 生成TS；不为匹配解释重构所有资源消费者。

## 6. 首页与首次使用：验证第一次有效操作

### 6.1 首页目标

优先显示有依据的取回线索，并保留返回工作区的便捷路径。区分“从 WorkTwill 打开”和“最近修改”，不按mtime推断阅读，不将工作区手动顺序冒充最近访问。

系统接受打开请求并经复验记账，不代表默认软件加载成功或用户已阅读。没有打开历史时如实表达，不伪造示例、热度或“刚才的工作”。不预设5–8条、固定混排公式或首屏必须塞入动态与收藏摘要。

### 6.2 首次价值任务

> 新用户首次授权普通文档目录，不创建工作区，在首批资料可用后，独立找到一份需要的资料并打开正确原件；同时能理解最近修改提供了什么帮助。

验证过程：选择目录 → 首批可用 → 用户按真实线索查找 → 判断结果 → 打开原件 → 说明是否更容易找回资料。首次收藏或加入工作区可作为后续动作，不强迫它们成为获得价值的前提。

分别记录授权到首批可用的等待，以及首批可用到完成任务的用时、误操作和所需提示。没有实测前不承诺“立刻”或固定五秒。引导弹窗、扫描完成、资料数量与创建工作区均不能替代这个任务。

### 6.3 状态真实性仍是前提

读取中、首次读取失败、从未授权、用户取消、扫描尚无首批、扫描完成空目录、已有资料无打开记录要行为正确。复用现有机制，不为每个状态新增常驻说明或独立错误状态。

可用性观察建议邀请少量不了解内部设计的目标用户，用不建工作区的任务先验证首个收益，再观察跨日复用。小样本帮助发现问题，不证明市场优势或留存；试用观察不重新变成工程持续运行的前置条件。

## 7. 时间线、关系与异常行为

### 7.1 时间线按证据整改

本轮验证受影响路径的历史正确性和默认可读性：先区分工件噪声、首次收录、无变化重扫和真实高频修改，再决定是否聚合。81,168条记录只能说明数量大，不能单凭截图判定重复入库。

若实施聚合，先按历史授权过滤，再按可信观察对象、事件类型和明确时间规则分组。重新指向/合并可能保留同一UUID，因此不只按当前UUID合并；未知身份不猜连续性。不改写kind、mtime、观察时间及来源。跨页、跨日、时间模式、组数/次数与游标版本同批说明；五分钟不预定为正式窗口。

### 7.2 关系的作用范围

| 操作 | 应改变 | 必须保留 |
|---|---|---|
| 从A移除 | 仅A区引用 | B区引用、收藏、源文件 |
| 取消收藏 | 收藏状态 | 工作区关系、源文件 |
| 删除工作区 | 该区及其关系 | 其他工作区和源文件 |
| 明确移到B | 成功项的目标/来源引用 | 失败项来源、其他引用和源文件 |
| 单区移除网页 | 该区关联 | 网页全局记录、其他区及收藏 |
| 全局删除网页 | 按既定确认处理全局网页关系 | 不伪装为单区移除，不修改网站 |

完整工作区目标保持可达，不同时删掉常驻目标和完整侧栏而只留几个常用项。拖拽保留点选目标的等价路径。无目录、无工作区时保存网页仍可用。

### 7.3 异常语义

仍授权但暂不可用，可保留已有名称与关系；最后授权撤销后，全局入口隐藏名称路径，工作区匿名占位；仍有其他有效授权时继续可用；同路径换对象不能静默继承。已验证范围内同物理对象移动不一律要求人工修复。

返回按动作区分：关闭弹层、完成/取消关联、完整结果返回来源、进入另一工作区后导航，不统称完整历史恢复。权限或版本变化优先于旧结果、选择和游标恢复。基本键盘、可见焦点、无拖拽路径和中文组字保护随相关改造回归，不整体后置为P2。

## 8. 实施优先级与完成条件

P0表示本轮核心产品质量目标，不表示当前用户已经要求继续编码。对具体缺陷按证据修复；没有问题不重复改造已有能力。
